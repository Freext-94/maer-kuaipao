## 1. 改造后的产品边界

> **术语（v3）**：所有单子统一叫「订单」；客户欠款页面/记录叫「客户账单」；单笔金额明细叫「订单明细」；「累计欠款」改「账单合计」；「今日已收」改「累计收回」。文档内部仍可能用“欠款”描述金额概念，但 UI 文案不得出现。

### 保留
- 电话录单、派单、商家备货、取货、送达、结单、冲正、取消。
- 客户欠款台账：只记「谁欠多少、欠哪单、什么时候还了多少」，用于事后追缴。
- 订单账单：单笔订单的货款/服务费/附加费/优惠/调整/已收/未收。
- 多业务：代买跑腿、代取送、代办、接送、代驾（可扩展）。
- 权限：超级管理员 / 管理员 / 骑手 / 商家 / 客户，多角色、工作区切换。

### 明确不做
- 账期、月结、信用额度、授信、超额拦截、自动停单。
- 月结对账单、客户「我确认无误」、对账单免登链接。
- 免登链接、链接即身份、链接吊销。
- 在线支付、微信登录、短信、订阅消息、地图计费、智能派单。

### 一句话
> 这是一个「接单 + 履约 + 记欠款」的内部经营工具；欠款只负责记清楚、查得到、方便要，不负责授信和风控。

### 2.2 关键条目说明

#### #2 账号与权限（删除免登后的版本）

**目标**
- 所有角色统一 `/login`，手机号 + 密码。
- 角色：`super_admin`、`admin`、`rider`、`merchant`、`customer`；一个人可多角色。
- 登录后按角色生成工作区；多工作区让用户选：调度台 / 商家工作台（可多店）/ 骑手端 / 客户端。
- 用户管理：新建、编辑角色、绑定商家、启停、重置密码、强制改密。
- 权限矩阵：超管管理所有权限；管理员按矩阵授权；默认管理员拥有订单/客户/商家/骑手/账单/设置等平台维护权限，但不默认拥有用户/权限管理。
- 删除 `t_access_token` 及所有 `?token=` 入口；`/api/m|r|c/**` 改为账号会话 + 角色校验。
- 客户账号由管理员在建立客户档案时一并创建（手机号 + 初始密码），客户登录后可改密码、看自己的单和欠款。
- 不再有「链接即身份」；泄露风险从"转发链接"变成"账号密码"，因此必须有重置密码和停用。

**数据**
```
t_user (phone 唯一, password_hash, must_change_password, status, last_login_at)
t_user_role (user_id, role, scope_merchant_id)  多对多
t_permission (code, name, group_name)
t_role_permission (role, permission_code)
t_customer (user_id, note)  ← 去掉 billing_cycle / credit_limit_fen / settle_day
```

**登录流程**
```
手机号+密码 → 校验 → 列出工作区
  ├─ 1 个 → 直接进
  └─ 多个 → 工作区选择 → 进对应端
```

**权限码**：订单 7 项、客户 3 项、商家 3 项、骑手 3 项、钱 3 项、设置 3 项、用户 4 项、权限 1 项，共 27 项。详见原型「用户与权限」页。

**迁移**
- `staff` → `admin`；初始账号 `13800000000` → `super_admin`。
- 现有商家/骑手/客户 `password_hash` 为空：登录提示"账号还未设置密码，请联系管理员"，由管理员重置，**不设统一默认密码**。
- 删除 `t_access_token` 表与相关代码；删除 `ShareBillView`、`ShareController`。

#### #8 取消账期/额度后的客户与欠款

**客户档案只剩**：姓名、手机号、备注（习惯/门禁/常买啥）。

**结单**：
- 应收 = 货款（实付优先，否则估价）+ 服务费 + 附加费 − 优惠 + 冲正/减免。
- 当场实收由收银人填，0 ~ 应收；差额自动成为该客户欠款。
- 没有"赊账/货到付款/月结"选项，没有额度红线，没有超额拦截，没有自动停单。

**欠款页**：
- 客户列表：姓名、备注、手机号、欠款合计、最近下单、最近还款。
- 客户详情：未结清订单逐笔（单号/日期/应收/已收/未收）、收款记录、导出/打印催缴单。
- 登记收款：金额、方式、备注；可指定某单，也可按最老欠款自动冲。
- 只做"记录 + 查询 + 催缴"，不做信用评估。

**数据**：`t_ledger_entry` 仍是唯一真源；`t_monthly_bill` 删除（或先停用后清理）。

#### #12 账单系统（无月结版）

三层：
1. **订单账单**：单笔订单的金额明细 + 收款记录 + 凭证，可打印。
2. **账单页**：订单账单 + 收款流水同页；默认今天；按年月筛选；货款/跑腿费分列；顶部今天跑腿费/昨天跑腿费/累计欠款。
3. **客户欠款**：按客户汇总的未收订单 + 还款记录 + 催缴单。

不做：月结账期、客户确认、免登分享、账单快照表。账单全部由订单和流水实时推导。

#### #13 多业务平台

- `t_service_type`：`buy` 代买跑腿、`pickup` 代取送、`errand` 代办、`transfer` 接送、`driver` 代驾；后台可新增类型、上传 icon、配置额外表单字段（`form_schema`）。
- `t_order.service_type` + `t_order_service` 扩展（起点/终点/预约时间/时长/车牌/车型/服务内容）。
- `merchant_id` 可空；代买用 `t_order_merchant` 商家组（v3 R1）；`flow_kind=buy` 才走商家备货和垫付。
- 计费一期：每类默认服务费 + 手改；二期再做公里/时长。
- 状态继续复用 8 个，按 `flow_kind` 决定流转和文案；需要时再加 `IN_SERVICE`。
