# 08 · 架构（Architecture）

> **对应审查条目**：F18（数据库迁移与回滚策略）+ 整体架构补全。
> **原则**：最小复杂度、向后兼容。不为未来业务提前建设复杂组件。
> **来源**：整合 `docs/design.md` 的架构章节，并按本次审查补充迁移回滚策略。

---

## 1. 一句话架构

一个 Spring Boot 单体 + 一个 Vue3 静态站 + 一个 MySQL。没有 Redis、没有消息队列、没有微服务：日均 <50 单、1–3 个使用者，多一个组件就多一份运维负担，而这个系统的使用者不是运维人员。

```
浏览器/手机 ──HTTPS──> nginx(web) ──┬── 静态文件  frontend/dist
                                    ├── /api/*    → backend:8080
                                    └── /files/*  → uploads 卷（nginx 直发，不走 Java）
backend ── JDBC ──> mysql(卷)
```

## 4. 关键架构约束

### 4.1 派生值不落库

`receivable`（应收）、`paid`（已收）、`owed`（未收）全部由查询算出，避免"字段和事实打架"（呼应 I-2）。

### 4.2 台账只追加（三道防线）

1. Service 层：`LedgerService.post()` 唯一写入口，无余额 setter；
2. DB 层：`BEFORE UPDATE`/`BEFORE DELETE` 触发器 `SIGNAL SQLSTATE '45000'`；副作用——清库不能用 DELETE，用 `flyway.clean()`；备份恢复走 `mysqldump`；
3. 自检：`HealthService.issues()` 每次刷新逐单/逐客户核对。

### 4.3 通知主路径是轮询

| 渠道 | 机制 | 配额 |
|---|---|---|
| POLL | 商家页面每 12 秒拉取 | 无限制，主路径 |
| GROUP_MSG | 复制文本人工发群 | 无限制，兜底 |
| MANUAL | 电话 | 无限制，永远保留 |

`T_notify_record` 落库每次触达。浏览器不允许无手势自动播放声音 → 商家端保留"声音自检"按钮。

### 4.4 凭证文件边界

小票/送达照落本地磁盘（`PAOTUI_UPLOAD_DIR`），数据库存相对路径 + 哈希。文件名随机串，URL 即能力凭证。边界：知道 URL 就能看图；对外暴露前加 nginx Referer/内网限制或签名 URL。

## 5. F18 · 数据库迁移与回滚策略（本次新增）

### 5.1 迁移约定（`CONFIRMED`）

1. 只有一个迁移目录 `backend/src/main/resources/db/migration`，它是结构唯一真源；`database/demo-data.sql` 只是可选演示数据，不含结构。
2. **迁移只加不改**：已发布的 V1 永远不动；改结构加新脚本（V9、V10…）。
3. 生产 MySQL 必须开 `log_bin_trust_function_creators`（`docker/my.cnf`），否则应用用户建不了 V1 触发器（ERROR 1419）。
4. `t_ledger_entry` 的触发器让 DELETE 失败，清理脚本注意。

### 5.2 回滚策略（`PROPOSED`，防止重构破坏数据）

> 审查意见强调 F18 尤其重要——重构时防止破坏已有数据。

| 场景 | 策略 |
|---|---|
| 迁移执行前 | 强制一次 `mysqldump` 全量备份（对应 A37） |
| 结构变更 | 只加列/加表，不删列、不改列义；用默认值兼容旧数据 |
| 数据回填 | 在新迁移脚本里做幂等回填（可重复执行） |
| 回滚 | Flyway 社区版不提供自动 undo → 用备份恢复（A38 实际演练） |
| 终态校验 | 迁移后跑 `HealthService.issues()`，不平立即报警 |

**重构期特别约束**：
- 状态机迁移（V4）等涉及枚举值改动的，必须有 `UPDATE ... SET status=...` 的旧→新映射，且映射前先备份；
- 涉及财务字段的迁移，迁移前后必须核对台账合计一致。

### 5.3 迁移实跑记录

见 `specs/migration-run.md`（V1–V8 执行成功，12 tests 通过）。新增迁移后须更新该文件。

## 6. 部署方案

- 单实例：nginx + backend:8080 + mysql，均 Docker 化；
- 卷：uploads（文件）、mysql data（数据库）必须持久化；
- 时区：Docker 容器、数据库、应用三层时区显式配置（02 §A4 规则 7）；
- 备份：`mysqldump` 定时备份 + 实际恢复演练（D3 A37/A38）；
- RTO：单实例宕机即停摆，可接受约 4 小时（重部署 + 恢复最近 dump）。

---

## 7. 已知取舍（`CONFIRMED`）

1. 逻辑删除只用于主数据；台账、状态日志、分配表没有 `deleted` 字段（给只追加表加软删等于开后门）。
2. 没做多租户 `tenant_id`：单个服务商自用，加常量列是噪音。
3. 单实例部署，宕机即停摆，RTO 约 4 小时。
4. 一期不做营销/优惠券/预存体系、多租户、微服务、Redis、消息队列、在线支付。
