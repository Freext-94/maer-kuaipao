## 两套分类法（分清层次）

- **问题四类（01 §0.1）**：`CONFIRMED` / `PROPOSED` / `IMPLEMENTATION_GAP` / `UNDECIDED` —— 回答"这条规则是什么性质"，用于所有规格条目。
- **漂移七态（01 §0.2）**：上面四类 + `IMPLEMENTED` / `NOT_IMPLEMENTED` / `SPEC_GAP` / `DEPRECATED` —— 回答"这个 Gx 漂移点处在修复流程哪一步"，仅用于 07-gaps.md。

**关键纪律：绝不把"代码已实现"等同于"业务规则已确认"。**

## 待裁决冲突（U 编号）

全局 U-01 ~ U-11 汇总在 `01-constitution.md §5` 与 `07-gaps.md §4`。裁决后须新增 ADR 并更新所有引用文档。

## 变更流程（spec-first）

1. 新功能：先改 specs → 评审 → 再改代码 → 测试映射到验收编号 → 提交信息引用 spec 编号（如 `feat(B3-T3): ...`）。
2. Bug 修复：先在 spec 中补充/修正条目（或 ADR），再修代码。
3. 规格与代码冲突：不得"顺手"改代码绕过 spec；必须先更新 spec 并记录 ADR，再改代码。
4. 提交信息约定：`<type>(<spec-id>): <summary>`。

## 编号约定

- 批次：B0–B5（见 `docs/需求与改造计划.md`）
- 任务：Bx-Ty（如 B3-T3）
- 验收：Axx（A1–A31 + D3 新增 A32–A40）
- 不变式：I-1 ~ I-3
- 漂移点：G1–G18
- 待裁决：U-01 ~ U-11
- ADR：ADR-NNNN
